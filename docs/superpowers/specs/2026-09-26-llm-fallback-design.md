# LLM Fallback — Draf Desain (butuh keputusan)

Tanggal: 2026-09-26. PRD: §4.6, §6.3, §6.6, R6, R7. Status: **draf untuk direview**. Belum ada kode; bagian "Keputusan terbuka" perlu dijawab sebelum implementasi.

## Ringkasan usulan

Model **tidak** menghasilkan daftar aksi per file. Model menghasilkan **`Command` yang sama dengan output parser** (verb + seleksi: glob, `files`/`dirs`, umur, ukuran, `in`, tujuan), dalam JSON yang dikunci grammar GBNF. Sesudah itu jalurnya identik dengan perintah rule-based: `planner::build` → Validator → preview → eksekusi.

Alasannya:
- Output kecil dan terstruktur, jadi model 1.5B/3B jauh lebih akurat daripada kalau harus menyebut ratusan path.
- Planner, Validator, dan preview yang sudah dites dipakai ulang. Model tidak pernah menyentuh path hasil ekspansi.
- PRD bilang "skema yang sama dengan parser"; parser memang menghasilkan `Command`, bukan `ActionPlan`.
- Whitelist tetap ditegakkan oleh tipe: `Command` hanya punya enam verb.

## Alur

```text
Enter di panel
  -> parser::parse OK?  ya -> jalur rule (sudah ada)
                         tidak -> model terpasang? tidak -> error + 3 contoh (sudah ada), resolved_by=none
                                                   ya    -> [worker LLM] infer(input, metadata) -> JSON
  -> serde -> Command -> planner::build -> Validator -> preview berlabel "Generated by AI" -> run
  -> command_history resolved_by='llm'
```

## Komponen

- **Crate `llama-cpp-2`** di belakang **cargo feature `llm`** (default mati di CI; nyala di paket rilis). Build tanpa feature tidak butuh cmake atau llama.cpp sama sekali, dan panel berperilaku seperti sekarang.
- **Worker LLM**: satu thread yang memiliki model. Model dimuat lazily saat pertama dipakai, lalu dipertahankan. Permintaan masuk lewat channel; pembatalan lewat `AtomicBool` yang dicek per token. Tidak ada jaringan (R4).
- **Prompt**: system prompt berisi skema singkat dan contoh few-shot dari PRD §4.5, ditambah **metadata** folder aktif (R6): maksimal N entri (usul 200) berisi nama, ukuran, jenis, dan waktu ubah. Tidak pernah isi file.
- **Grammar GBNF** yang membatasi output ke JSON `Command` (enum verb, field opsional, angka). Dibangkitkan dari satu sumber di kode supaya selalu sinkron dengan `Command`.
- **Konversi** `LlmCommand` (serde) → `parser::Command`: fungsi murni yang sepenuhnya dites.
- **Settings**: pemilih file `.gguf` (menyimpan `model_path` yang sudah ada di `Config`), ditambah link dokumentasi model yang direkomendasikan dan checksum-nya. Aplikasi tidak mengunduh apa pun.
- **UI**: status "Thinking…" dengan tombol Cancel di panel. Preview berlabel "Generated by AI". Kalau Validator menolak, alasannya ditampilkan (sudah ada).

## Test

- Murni (selalu jalan di CI): konversi JSON → `Command` termasuk input adversarial (verb di luar whitelist, path `..`, mode setuid, field asing); pembentukan prompt memotong metadata di N dan tidak pernah membaca isi file; grammar menerima semua contoh PRD dan menolak verb lain.
- Integrasi dengan model sungguhan: `#[ignore]`, hanya jalan bila `ANCHOA_TEST_MODEL=/path/model.gguf` diset.

## Keputusan terbuka (untuk pengguna)

1. **Bentuk output**: `Command` (usulan di atas) atau `ActionPlan` penuh seperti bunyi literal PRD?
2. **Cargo feature `llm`**: setuju default mati di CI dan build dev, nyala di PKGBUILD/Flatpak? Build llama.cpp menambah waktu compile dan butuh cmake + compiler C++.
3. **Model default yang didokumentasikan**: Qwen2.5-1.5B-Instruct Q4_K_M (lebih ringan) atau 3B (lebih akurat)?
4. **Batas metadata**: 200 entri cukup? Folder yang lebih besar dipotong, dan model hanya melihat contoh nama.
5. **Threshold confidence** (PRD §10): parser saat ini biner (cocok = 1.0, gagal = fallback). Tetap begitu untuk v1?
6. **Akselerasi GPU** (Vulkan/CUDA/Metal) ditunda? Usul: hanya CPU untuk v1.
